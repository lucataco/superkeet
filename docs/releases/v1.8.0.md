## Summary

Superkeet v1.8.0 makes Actions Mode act while you are still speaking and
carry out multi-step commands. Say "open the Notes app and create a new note"
and Notes opens about a second after you name it; when you finish, the command
is split into steps, the second step becomes ⌘N in Notes, and one plan card asks
for approval instead of a dialog per tool call. The bundled speech engine
(parakeet-cli v0.1.7, protocol 2) now streams interim text itself, so a single
recogniser produces both the early hint and the final transcript.

## What's Changed

### Instant app launch

- Saying "open ‹app›" / "launch ‹app›" (or "switch to ‹running app›") during a
  Command Mode recording opens the app as soon as the name is recognised in the
  running text — without waiting for you to finish speaking or approving it
  first. Only installed app names can trigger it; a misheard name does nothing.
  On by default under Settings ▸ Actions ▸ Instant App Launch.
- Interim text comes from the Parakeet engine when it speaks protocol 2
  (bundled v0.1.7), or from Apple's on-device recogniser on macOS 26 while an
  older engine is running. The final transcript always comes from Parakeet, and
  the command reuses the early launch instead of opening the app twice.
- The recording overlay's level meter and the interim recogniser now share one
  microphone tap (`MicrophoneTapHub`), so Command Mode hears audio even with the
  overlay style set to None.
- Early launches are written to the action log with the reason they fired; the
  HUD shows “Opened Notes” while you keep talking.

### Multi-step commands

- Commands are split at "and", "then", commas and semicolons (outside quotes)
  and run step by step. Each step tries the cheapest route first: already done
  by an early launch, a built-in open, a keyboard-shortcut recipe, then the
  on-device planner in a fresh session that is told what earlier steps did and
  which apps are already open.
- New built-in tool `press_shortcut {app, keys}` presses a chord such as ⌘N in a
  running app after bringing it to the front and confirming it is frontmost.
  Common verbs never reach the model: create/new → ⌘N (⌘T for a tab), save →
  ⌘S, close → ⌘W, undo/redo → ⌘Z/⇧⌘Z, select all → ⌘A, quit → ⌘Q.
- `open_app` now waits up to four seconds for the app to finish launching and
  show a window, and reports its pid and bundle identifier so later steps can
  target it.
- Compound open requests run with the built-in tools even when no MCP server is
  enabled, instead of failing before anything happens.

### Approvals and the HUD

- A multi-step command shows one **plan card** before anything runs: **Approve
  All** pre-approves exactly the native steps shown, **Step by Step** asks per
  call, **Deny** runs nothing. Steps handled by the model are marked *Planned*
  and their tool calls still ask individually.
- **Approve Similar** on a tool approval lets the same “changes state” tool run
  again for the same app or process during this command without asking; never
  offered for destructive tools; forgotten when the command ends.
- While a command runs the HUD shows a checklist of steps and tool calls whose
  status updates in place, keeps it on the result card, and only takes keyboard
  focus while a question is pending so Return/Escape work without capturing
  keystrokes from the app you were using.
- A whole-command deadline (default 180 s, Settings ▸ Actions) stops a stalled
  run independently of the per-tool timeout.

### Planner quality

- Read-only tools that describe live state (`list_windows`, `get_window_state`,
  `list_pages`, `take_snapshot`, …) always run fresh, and every successful state
  change drops cached read-only results, so the model never acts on a stale
  observation. Identical mutations are still reused, never repeated.
- Computer-use observations are projected into ranked, compact text for the
  model instead of being cut at 800 characters: a 185 KB `get_window_state` for
  Notes becomes ~630 characters with `[184] Button “New Note”` first. Screenshots
  are not requested unless the model asks, since it cannot see them.
- If a planned step overflows the model's context after tools have already run,
  the step continues once in a fresh session from a condensed record of the
  calls made so far, instead of failing.

### Native grounding and Actions Mode foundations

- Built-in `open_app` and `open_url` tools open apps and URLs through macOS
  directly; literal commands such as "open Discord" or "open Helium and go to
  youtube.com" run without a planner or MCP server.
- Optional native UI grounder (Settings ▸ Actions ▸ Native UI grounder): a local
  GLiNER fine-tune selects the exact control for single native clicks and text
  entry through Cua Driver, with a fresh accessibility observation before and
  after each approved action and no automatic retries.
- Cua Driver is seeded as a second default MCP server (disabled until enabled);
  its tool annotations drive the approval classification. Active/current-tab
  commands bind to one Chrome DevTools connection, with focus verification and a
  Cloudflare DNS deep-link template.
- Escape cancels a running action once (and still reaches the focused app);
  action runs own their step budget, result cache and in-flight approvals, so a
  cancelled or superseded run can never overwrite a newer one.
- Command Mode applies phrase replacements only, so filler removal and spoken
  edits cannot alter command arguments. MCP server environment secrets move to
  the Keychain; the `chrome-devtools` default gains `--autoConnect` through a
  guarded migration.

## Speech engine

Bundles [parakeet-cli v0.1.7](https://github.com/lucataco/parakeet-cli/releases/tag/v0.1.7)
(daemon protocol 2). A `start` command carrying `"partials": true` streams
interim `partial` events roughly every 0.75 s of captured audio; sessions that
do not ask for them, including every dictation recording, produce exactly the
protocol-1 event stream and cost the engine nothing extra. Superkeet accepts
protocol 1 or 2, so an older engine still works (without interim text from the
engine).

## Install / Upgrade

Download `Superkeet-1.8.0.zip` from this release and move Superkeet to
Applications. Release packaging signs and notarizes the app and includes a
SHA-256 checksum file.

Homebrew updates become available after the tap has been synchronized:

```bash
brew update
brew upgrade --cask lucataco/tap/superkeet
```
